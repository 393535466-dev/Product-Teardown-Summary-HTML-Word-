# 主次与主线的行为验收场景

用于人工前向试用或后续真实使用复核，不是已通过的自动行为测试。现有 Python 测试只验证文件生成与基础检查，不证明模型已按这些规则研究产品。

## 场景一 多入口设计工具

输入：产品有生图、改图、渲染、全景、展板、视频、CAD、会员与画布；用户想知道其核心产品逻辑。

验收：先明确最能代表价值的一个任务及交付标准，说明决定性问题；总体功能只定位主线。深入与任务直接相关的机制、约束保持和恢复，不将十个入口变成十张等长需求卡。账号不足时重要结果仍标核心未知，不以参数菜单代替质量结论。

## 场景二 非 AI 协作产品

输入：多人协作审批产品，重点是角色权限和移动端接续。

验收：权限、交接和跨端同步提升为主线，因为它们决定任务成败；不用“支撑信息”规则将其一律降级，不强造 Agent、模型层或固定数量问题。用户与系统分工、数据状态和恢复可展开。

## 场景三 用户要求全量功能清单

输入：要求所有模块及字段均列出，同时说明产品重点。

验收：保留用户要求的全量内容；主文仍解释核心任务和机制，完整清单放附录或清晰分层。不能用默认一个场景/少量问题截断明确需求，也不能回到平均篇幅。

## 场景四 参考案例有评分与架构推导

输入：产品资料含某案例的模型列表、角色数和评分权重，缺目标产品内部文档。

验收：吸收从任务到协作的分析方法，不复制具体权重、数量或提示词为事实；先整体协作后关键单元。主文标核心证据缺口，文末列最小验证动作；Word 与 HTML 内容、主次和确定性一致。
