# 清晰易读的 HTML 交付

完成研究和证据整理后，与 Word 文档一起生成真实 HTML 文件；两种形式共享分析内容，按 document-output.md 核对一致性。报告是面向阅读的分析成果，不是网站开发项目；无需为了排版引入构建工具或在线图表库。用户另有明确格式要求时遵循。

## 信息组织与主次

主文遵循 report-template.md 的顺序：产品和主场景 → 场景体验与交付 → 同一任务的分层机制 → 整体架构与关键结论。首屏说明核心问题、主要判断与重大限制；主目录围绕主线，不能将字段、端形态、证据、全部功能等都提升为同等一级入口。

- 主线深拆：核心场景的结果、流程、关键机制和修改恢复在正文展开；核心未确认项就地可见。
- 支撑简述：市场/商业/竞品/端形态/收费通常放在解释对应机制的位置，必要时才升为正文重点。
- 附录备查：完整模块覆盖、非核心功能、字段/权限大全、详细来源和次要问题放折叠区；不能占据大量首屏卡片。

选最能解释问题的表达方式：关键取舍用短段落；同一任务的竞品差异与规则用紧凑表格；整体协作、数据引用用结构图；正向与恢复路径用流程图；界面机制用有来源的截图与说明。主观权重、模型/角色数量不画成无依据指标。

先画整体关系，再展开重要单元。图中标清已知与推断，页面标题写分析结论或问题，不只是堆功能名。不要另设重复的“用户感受”大章；体验证据附在对应流程步骤。每项内容只设一个主要解释位置，摘要导航、正文解释、附录核实。

不机械要求每节有图或表；状态有文字标签，颜色仅辅助。HTML 仍保留完整分析内容，不以折叠为由删掉与 Word 的关键细节。

## 生成方式

可直接写完整 HTML，或先编写主体片段，再使用标准库脚本套入模板：

```sh
python3 <skill-dir>/scripts/render_report.py <body.html> <report.html> --title '产品名 · 产品拆解' --subtitle '日期 · 端形态 · 体验条件'
```

`<skill-dir>` 用当前 Skill 的真实路径替换。脚本默认拒绝覆盖；明确修改同一报告时才加 `--overwrite`。不需要安装 Python 包。模板提供 `.lead`、`.note`、`.grid`/`.card`、`.status`/`.confirmed`/`.uncertain`/`.verify`/`.suggestion`、`.table-wrap`、`.diagram`、`.flow` 和 `.detail-body` 等样式，可按需改写。

主体片段自行组织 nav/section/table/figure/details/SVG，不限定 JSON 模式或固定图表种类。来源中的 `<`、`>`、`&` 等文字需转义后插入；脚本转义标题和副标题，主体作为模型编写的 HTML 插入，不是任意网页的安全净化器。不要直接拼接来源网页脚本、事件属性或不可信 HTML。

表格使用 caption/thead/th；目录链接对应唯一 section id。SVG 带 viewBox、可读标签和 title/desc，复杂图用可横向滚动容器；图中的不确定性与正文一致。禁止将 Mermaid 代码块当作已渲染的图；可改画内联 SVG 或实际渲染后嵌入。

## 资源与离线阅读

优先单文件：CSS 和必要脚本内联，流程图用内联 SVG；本地 PNG/JPEG/WebP 截图可编码为 data URL。截图较大时可使用报告旁的资源目录，交付时包含全部资源并说明多文件形式。不要让图片引用临时路径、仅存在于研究机器的绝对路径或失效在线地址。外部证据链接可以保留，正文离线仍可读。

默认保存到任务可写的 `outputs/product-teardown/<产品与日期>/`，选择不覆盖已有文件的名字。网页源、私有截图、账号与项目数据不自动提交 GitHub；更新 Skill 只发布模板和方法。只有用户明确要求公开某份报告时才发布对应内容。

## 生成后的验证

1. 检查标题、范围、关键结论、图中分支、需求卡和证据状态一致，未读/未测部分没有写成事实。
2. 用可用浏览器打开真实文件或本地预览，检查桌面和窄屏（约 390px）：正文无页面级横向溢出，长表/大图只在自己的容器滚动，字不重叠，图片可见。
3. 点击目录与折叠项；折叠区包含的缺口不能与首屏结论冲突。打印样式要展开 details、重复表头、保留证据和图像；有打印预览工具时检查预览。
4. 检查单文件不依赖 CDN；多文件引用都可解析。避免只验文件存在而未看页面。浏览器或打印预览不可用时准确说明验证范围。

最终同时给实际 Word 与 HTML 文件链接和少量核心结论；不再粘贴一份重复全文。生成失败时修复可处理的问题，不能把原始 HTML 源码宣称为已生成可读文件。用户要求在线部署时，再使用当前可用且获授权的发布流程；默认生成本地文件。
