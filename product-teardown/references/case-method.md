# 飞书案例的方法映射

来源：[以 OiiOii 为例拆解一个 Multi Agent 平台](https://qiif643fw66.feishu.cn/wiki/FURJwrpJ0i3efOkPauKcRxbTnVh)，2026-10-20 重新浏览：拆解思路画板、场景与评测、定位目录、功能与正逆向路径、技术协作与全局上下文，以及模型/基础/架构总结的层级。这里记录方法提炼，不保存原文、私人资料或案例截图；不要求后续每次都重新访问链接。

## 吸收的方法

| 案例中观察到的组织方式 | 本 Skill 的应用 |
| --- | --- |
| 先介绍产品，再选具体创作任务观察结果与过程 | 先定一个主场景和交付标准，先结果后解释机制 |
| 定位与差异紧扣用户任务 | 竞品、市场、商业用于解释场景选择，避免独立扩成大清单 |
| 使用路径同时考虑向前推进与修改返回 | 正向流程与恢复分支挂在同一业务链上 |
| 先看总体协作与共享信息，再逐个分析重要角色 | 先整体后单元，研究输入/处理/输出/规则及更新传播 |
| 模型与基础积累承接任务和协作，最后回到整体架构 | 模型、成本、数据与资产必须解释对主线交付的作用 |

## 本次新增的聚焦规则

这是针对用户“项散乱、没有主次”的修订判断，不是声称案例作者规定了这些规则：
- 主线深拆、支撑简述、附录备查；不因模板存在就给所有项同等篇幅。
- 常规从一个主场景及少量决定性问题开始；用户的专题或全量要求优先。
- 用户视角融入场景验证；PRD 视角用来解释规则、状态、分工与验收。
- 关键未知保持正文可见；旁支字段和完整覆盖表后置。

## 保留的边界

案例的评分权重适用于它的测试目标，不复制为所有产品的固定比例；未实测不打效果分。案例里的具体用户规模、角色数量、模型清单、提示词或后台流程也不是目标产品事实。实现推导保留为假设或复现方案。

产品不是 Multi Agent 时，使用业务单元/系统服务解释分工，不制造角色。继续保留端形态、竞品与三级确定性，以及内容一致的 Word＋HTML 双文件。

## 用知末作为聚焦示意

仅说明选题方法，不是本轮重测知末：可选“用已有客厅设计图替换沙发材质，同时保留门窗、墙体和视角”作为主场景。

主线可深入素材与约束表达、修改方式与选区/指令、非目标保持、结果比较与再修改；模型选择、会员消耗和历史接续作为影响该任务的支撑。全景视频、CAD、展板等其他入口概览或附录，不再逐一抢占正文。若收费或跨端接续本身被指定为重点，则提升为主线。
